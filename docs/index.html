Changed lines only

Coverage for the lines a pull request actually changed.

mo3ta-coverage finds changed JavaScript and TypeScript files, maps them to likely Jest tests, runs those tests, and fails when changed-line coverage is below your threshold.

GitHub npm mo3ta.top

How it works

One command, aimed at the diff. It does not try to re-grade the whole repository.

01

Changed files

JS and TS files changed versus a base ref, including every author’s commits, plus staged and unstaged edits.

02

Related tests

Maps each source file to likely tests by filename and, in smart mode, by walking imports backward.

03

Jest

Runs the local Jest binary with coverage. --dryRun true prints the test paths and stops.

04

Changed lines

Reads coverage/lcov.info and counts only coverable lines that differ from the base. Default limit is 80%.

Three ways to pick tests

Smart is the default. It catches specs that reach a changed file through a barrel or a thin wrapper without walking the whole graph.

fast

Name, then a direct import

Looks for .test and .spec files, __tests__, and a parallel src/tests layout. If the name misses, it scans test files that import the source directly.

Default

smart

Name plus reverse imports

Same naming matches, then a reverse-import walk limited by --depth. Depth 1 is a direct importer. Depth 2, the default, also crosses one intermediate module.

full

Let Jest expand

Passes the changed source and test files to jest --findRelatedTests. There is no depth cap. --dryRun can only list the changed test files in this mode.

Install and run

Use the published package, or run the latest commit from GitHub without cloning.

shell 
npx mo3ta-coverage --mode smart --base origin/main --limit 80

# latest commit, no global install
npx github:MahmoudMabrok/mo3ta-coverage --mode smart --base origin/main --limit 80

npm install -g mo3ta-coverage

Save defaults in the project root. Later runs pick up base, mode, and depth from that file when you do not pass them.

.mo3ta-coverage.json 
mo3ta-coverage config --base origin/main --mode smart --depth 2

Pass --files src/a.js src/b.ts or --files src/a.js,src/b.ts, or a newline-separated list via --filesFrom, when you want to choose the files yourself. Changed lines for those files are still computed against --base.

GitHub Action

mo3ta-coverage-action runs the CLI on Node 20, turns on CI mode, and appends the markdown table to the job summary. Leave base empty and it picks the ref from the event.

EventBase used
pull_requestThe pull request’s base commit
pushThe previous commit (HEAD~1)
schedule, dispatch, otherorigin/main
.github/workflows/changed-line-coverage.yml 
name: Changed-line coverage

on:
  pull_request:
  push:
    branches: [main]

jobs:
  changed-line-coverage:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - run: npm ci
      - uses: MahmoudMabrok/mo3ta-coverage-action@v1
        with:
          mode: smart
          depth: 2
          limit: 80

Checkout needs full history so the merge-base diff is available. Inputs are documented in the action README.

MCP server for coding agents

The same checks ship in mo3ta-coverage 1.3.0 and later as MCP tools over stdio. The bin is mo3ta-coverage-mcp. An agent can list the diff, see which tests would run, and read the uncovered lines it should cover. The server calls the CLI’s own functions. It needs Node.js 18 or newer.

  • list_changed_filesList JS/TS files changed versus a base ref, or an explicit list.
  • map_related_testsMap those files to the tests fast, smart, or full mode would run. In full mode this lists the changed test files; Jest expands the set when a check runs.
  • check_changed_line_coverageRun the changed-line check and return uncovered lines with source text. runTests: false grades an existing lcov.info instead.

Each tool takes a root path. If you omit it, Claude Code’s CLAUDE_PROJECT_DIR is used when set, otherwise the server’s working directory. useConfig defaults to true, so base, mode, and depth come from .mo3ta-coverage.json when that file exists. check_changed_line_coverage runs the repo’s local Jest (default timeout 5 minutes) and writes coverage/ there. A missed threshold comes back as data, with the uncovered lines, rather than a crash. A missing git repo, a bad base ref, a missing Jest install, or a timeout comes back as a tool error.

Cursor and other MCP clients

Use npx as the command. The same JSON works in .cursor/mcp.json and in Claude Desktop’s claude_desktop_config.json.

.cursor/mcp.json 
{
  "mcpServers": {
    "mo3ta-coverage": {
      "command": "npx",
      "args": ["-y", "--package", "mo3ta-coverage", "mo3ta-coverage-mcp"]
    }
  }
}

Claude Code

shell 
claude mcp add mo3ta-coverage -- npx -y --package mo3ta-coverage mo3ta-coverage-mcp

The package name and the bin name differ, so npx needs --package mo3ta-coverage. From a checkout of this repo, node mcp/server.js starts the same server.
